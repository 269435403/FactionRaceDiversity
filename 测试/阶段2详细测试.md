## 零、阻断缺陷优先复测

以下测试未通过前，不继续其他第二阶段验收。测试时必须使用本轮重新构建后的 DLL，并在启动后先打开一次设置以完成 schema 6 迁移。

### 0.1 设置页检查

1. 打开“选项 → 模组设置 → 阵营种族多样性”；
2. 确认阵营名称前有图标；
3. 确认默认看不到隐藏阵营和不可用阵营；
4. 分别勾选“显示隐藏阵营”“显示不可用阵营”，确认它们可随时显示；
5. 选择文明外来者，确认无需勾选任何启用框就能直接看到全部 Race 比例；
6. 拖动任一比例后确认名称变绿并移动到列表顶部；
7. 确认 Race 列表只显示真实人物种族，不再出现第二个“人类”、人类尸体、异常人类尸体、鼠族尸体或萌螈族尸体；
8. 将鼠族或萌螈族权重设为正数，确认其下方自动出现独立异种比例区，不存在“自定义异种比例”复选框。

### 0.2 鼠族 100%

1. 文明外来者：Human 0、Ratkin 100、其他 Race 0；
2. 鼠族异种池：`RK_XenoType_Ratkin` 对应鼠族异种 100，其余 0；
3. 分别触发敌对袭击、军事支援、商队、访客；
4. 统计所有可替换人形成员，商队驮兽不计；
5. 通过标准：普通袭击者、援军、商人和护卫均为鼠族；固定领袖或明确特殊人物单独记录，不得出现大量静默回退人类。

### 0.3 萌螈族 100%

1. 文明外来者：Human 0、Axolotl 100、其他 Race 0；
2. 萌螈族异种池：萌螈种 100，其余 0；
3. 重复袭击、军事支援、商队和访客测试；
4. 通过标准：所有普通可替换人形成员均为萌螈族，不能再出现“生成很多人只有一个萌螈族”。

### 0.4 鼠族/萌螈族 50/50

1. Human 0、Ratkin 50、Axolotl 50；
2. 至少累计生成 200 个普通可替换人形 Pawn；
3. 通过标准：鼠族和萌螈族长期统计各接近 50%，人类接近 0；允许正常随机波动，但不允许目标候选大量被过滤。

### 0.5 三 Race 独立异种池

分别设置：

```text
Human：Hussar 100%
Ratkin：鼠族异种 100%
Axolotl：萌螈种 100%
```

再将三种 Race 都设为正权重。通过标准：

- Human 只从 Human 池抽取；
- Ratkin 只从 Ratkin 池抽取；
- Axolotl 只从 Axolotl 池抽取；
- 三个池的百分比各自独立，不互相稀释；
- 战斗队伍不会抽取不能作为战斗人员生成的异种。

### 0.6 玩家自定义异种预设

1. 在原版异种创建界面保存两个预设：普通可战斗预设，以及包含禁用暴力基因的预设；
2. 重新打开本模组设置，确认两个预设自动出现在 Human 和每个正权重 HAR Race 的“玩家制作的预设”区，初始权重均为 0；
3. 将 Human 设为 100%，普通预设设为 100%，分别生成访客、商队和普通袭击，确认使用该预设且 `ForcedXenotype` 没有与 Custom 基因叠加；
4. 将禁用暴力预设设为 100%，确认和平人物可以使用，但袭击、军事支援等战斗请求安全回退到同池可战斗候选；
5. 在 Ratkin 或 Axolotl 池中把普通预设显式设为 100%，确认只有该 Race 使用它；外观或基因不兼容应由玩家取消该正权重，不得自动猜归属；
6. 覆盖同名预设文件后确认权重保留；重命名后确认作为新预设以 0 权重出现；删除文件后确认旧预设立即停止参与抽取，已有 Pawn 和存档仍可读取；
7. 让任务或第三方入口提供硬指定 `ForcedCustomXenotype`，确认本模组原样保留，不替换 Race、Def 或 Custom；
8. 主菜单无当前游戏时打开设置，确认可以读取磁盘预设且没有空引用或红字。

### 0.7 手动兼容、自动回退与原始规则

1. 在文明外来者 Ratkin 100% 下生成访客、商队和定居点人物，重点确认原 `Villager` 使用鼠族平民、原 `Town_Trader` 使用鼠族商人、原 `Town_Councilman` 使用鼠族领袖；

3. 连续触发普通、工兵/破墙类袭击；Human 0 时所有实际队伍人形成员必须为 Ratkin 或 Axolotl，不允许以 `Villager`、`Town_Councilman` 或无精确角色为由保留 Human；
4. 生成商队并分别检查商人、护卫、奴隶等人形商品；驮兽不计。所有人形商品必须使用外层商队派系的 50/50 配置；
5. 点击百族同盟与粗野百族同盟的“遵循原始规则”，确认所有当前 Race 等权，同时名称恢复普通颜色并退出置顶；保存、重启及新增 Race 后仍维持自动均分且不绿色置顶；
6. schema 5 旧设置迁移后，外来者已保存的非默认比例必须继续生效，两个内置阵营的原始状态必须恢复永久均分。

### 0.8 开发者诊断

执行“Output configured faction race report”。确认文明外来者报告包含：

2. 平民应使用美狐居民，战斗成员使用美狐步兵/突击队，商人使用美狐商人，领袖使用美狐领袖；狙击、重火力和破墙请求分别检查狙击手、机枪手与破障手，不得回退 Human。
3. 在 `SR_Faction_Pirate` 上分别设置 Ratkin、Kiiro、Milira、Miho 100%，确认该派系的机械组选项保持机械单位，Humanlike 成员才接受 Race 替换，且不会统计机械单位为意外种族。
4. 美狐异种池只应包含天狐、极地天狐、沙漠天狐、高地天狐、高魅力天狐；启用 Odyssey 时追加虚空天狐。智人种不得显示；来源 XML 中概率为 0 的 Baseliner、Dirtmole、Genie 等不得显示为美狐原生异种。
5. `SR_Faction_SRC` 不应因没有普通 PawnGroup 被错误标记为完整可配置派系；`SR_Faction_SRC_Researcher` 的任务教授保持原任务生成，不进入普通队伍替换。
6. 保存、退出并重载后复测，开发者报告中的意外 Human、Race/PawnKind 不一致和 `NoCompatiblePawnKind` 应为 0。

## 六、排除路径

分别触发并确认保持原始规则：

- 玩家开局人物；
- 没有手动映射且自动匹配也找不到安全候选的固定领袖；
- 新生儿；
- 变异体与异常实体；
- 固定头衔人物；
- 强制异种、强制基因、限定异种或人物类型回调的任务人物。

## 七、HAR 与异种联合

1. 为同一阵营开启种族和异种覆盖；
2. 选择一个 HAR 允许的异种，确认能正常生成；
3. 选择一个目标 Race 禁止的异种，确认不会产生空候选导致“无可用 PawnGroupMaker”或生成失败；
4. 检查日志中没有不断重复的反射或异种过滤错误。

## 八、阵营文化多样性联合

1. 启用阵营文化多样性和本模组；
2. 在文化模组中为同一阵营开启个人文化差异；
3. 在本模组中开启 Race 与 Xenotype 覆盖；
4. 生成袭击、商队和访客；
5. 确认同一队伍中能同时出现目标种族/异种和多种文化；
6. 确认固定领袖仍遵循文化模组的主要文化规则；
7. 确认本模组设置不改变阵营主要文化、人物文化或外交记录；
8. 保存重载后两套设置分别保留。

## 九、旧设置和旧存档

1. 备份并加载含旧 PackageID、`MPF_MixedCivil` 与 `MPF_MixedRough` 的存档；
2. 保留旧设置文件 `Mod_yyyyy_MixedPeoplesFactions_MPF_Mod.xml`；
3. 启动后确认旧全局异种权重只迁移到两个示例阵营；
4. 确认原版和第三方阵营没有被自动开启覆盖；
5. 确认旧存档中的既有人物、阵营和关系未被改写；
6. 保存新设置并重启，确认迁移不会重复覆盖玩家的新配置。

## 十、开发者检查

启用开发者模式，在 Debug actions 的“Faction Race Diversity”分类中：

1. 执行“Output configured faction race report”，检查已配置阵营、种族和异种权重；
2. 执行“Validate settings and reapply overrides”，确认设置正常时显示检查通过；
3. 手工把设置文件中的一个权重改成负数或非有限值后重启测试副本，确认异常值被修正且不引发加载错误。

## 十一、通过标准

- 未配置阵营完全保持原规则；
- 每阵营配置互不串扰；
- 两个示例阵营第一阶段行为回归通过；
- Core-only、Biotech-only、HAR-only 和完整组合均无本模组红字；
- 与阵营文化多样性同时运行时 Race/Xenotype 与 Ideo 同时生效；
- 多次保存、打开设置和存读档不重复注入、不丢设置；
- 特殊人物与既有人物不被强制改种族。






## 7. 特殊袭击 post-gear 验证回归

1. 使用开发者模式分别触发百族阵营的普通袭击/支援、工兵袭击、破墙袭击；启用 Anomaly 时再触发灵能仪式围攻。
2. 普通成员继续按 Race 权重生成。工兵、破墙手和仪式施术者只有目标 Race 存在对应角色时才替换。
3. 若目标 Race（例如只有单一通用 PawnKind 的瓦尔基里或派卡萨斯）没有特殊角色，仅该特殊人物允许保留原 Race。
4. 日志不得出现 `Generated pawn didn't pass validator check (post-gear)` 后连续 70/100 次耗尽。
5. 工兵队必须仍有可用工兵/破墙装备；灵能仪式围攻必须仍有合格施术者。
