# 阶段1详细测试

## 测试范围

目标模组：`D:\steam\steamapps\common\RimWorld\Mods\yyyyy_MixedPeoplesFactions`

- RimWorld：1.6
- 作者：`yyyyy`
- PackageID：`yyyyy.mixedpeoplesfactions`
- 最小依赖：Core；Biotech 为可选条件内容
- 不启动 RimWorld 的本地检查：XML 解析、静态键/defName、项目引用、Release 构建
- 下列游戏内项目需要人工启动游戏验证；本次制作流程不启动 RimWorld

## A. 本地自动检查

1. 使用 XML 解析器加载 About、FactionDef、两份 Keyed 和简中 DefInjected 文件，要求无语法错误。
2. 检查 `About.xml`：`packageId=yyyyy.mixedpeoplesfactions`、`author=yyyyy`、支持版本为 1.6，且 About.description 不含开发阶段文字。
3. 检查两个 DefName 恰好为 `MPF_MixedCivil`、`MPF_MixedRough`，无重复。
4. 检查所有 Keyed 键以 `MPF_` 开头，英文和简中键集合相同；DefInjected 只覆盖两个本模组 FactionDef。
5. 检查 C# 命名空间为 `MixedPeoplesFactions`，不存在 Harmony、HAR 或第三方程序集引用。
6. 检查 csproj 引用本机 Assembly-CSharp 与 Unity 模块，所有引用均 `<Private>False</Private>`。
7. Release 构建后检查 `1.6/Assemblies/MixedPeoplesFactions.dll` 存在且非空。

## B. Core-only 游戏内测试

最小启用列表：Core + 本模组，不启用 Biotech。

1. 开发者模式关闭，进入主菜单，确认无红字。
2. 打开「模组设置 → 百族同盟」，确认不显示异种滑条，只显示 Biotech 未启用提示。
3. 新建世界，在阵营配置页确认出现「百族同盟」与「粗野百族同盟」，且可自由增删。
4. 生成世界并进入地图，确认文明版不是天然敌对，粗野版保持天然敌对，聚落可生成。
5. 保存并重启游戏，确认无程序集加载错误或异种相关红字。

通过标准：Core-only 可加载、可生成世界、可读档；未启用 Biotech 时不会遍历或构建 XenotypeDef 权重。

## C. 默认值与设置保存测试

最小启用列表：Core + Biotech + 本模组。

1. 打开「模组设置 → 百族同盟」，确认 Baseliner 只出现一次，其他当前 XenotypeDef 各出现一次。
2. 不启用 Odyssey/不存在 Starjack 时，确认默认权重为 Baseliner 85、Hussar 5、Dirtmole 5、Genie 2.5、Neanderthal 2.5。
3. 启用 Odyssey/存在 Starjack 时，确认 Starjack 2.5 且 Baseliner 自动变为 82.5。
4. 其他模组添加的 XenotypeDef 应显示但默认权重为 0。
5. 修改任意权重，关闭设置窗口，重新打开确认数值保留；完全重启游戏后再次确认 ModSettings 保存成功。
6. 查看两个新阵营描述，确认「成员异种概率」随保存刷新，不显示旧缓存。
7. 点击「恢复默认」，确认当前 DLC 组合对应的动态默认值恢复。
8. 将全部有效滑条设为 0；下一帧/保存后应自动回写 Baseliner 100、其他当前异种 0，阵营描述也显示 Baseliner 100%。

通过标准：动态默认、唯一 Baseliner、设置保存、缓存刷新、全零回退全部一致。

## D. 战斗异种 100% 测试

Highmate 不能作为战斗人员，禁止用 Highmate 验证袭击者的 100% 异种设置。使用 Hussar：

1. 把 Hussar 权重设为 100，Baseliner 和其他全部设为 0，关闭设置窗口触发保存重建。
2. 开启开发者模式，在 Debug actions → Mixed Peoples Factions 运行 `Output current xenotype probabilities`。
3. 日志应分别列出 `MPF_MixedCivil`、`MPF_MixedRough`，Hussar=100%、Baseliner=0%。
4. 使用开发者工具触发 `MPF_MixedRough` 袭击，或为 `MPF_MixedCivil` 生成武装守卫。
5. 检查新生成战斗人员的基因页，应为 Hussar。至少检查 10 名；固定异种或特殊 PawnKind 需单独记录，不计入普通样本。
6. 改回默认并保存；再次生成新战斗人员，确认旧人物不变，新人物按新概率生成。

通过标准：普通新战斗成员与 Hussar 100% 设置一致，已有 Pawn 不被改写。

## E. Town_Trader / Highmate 例外测试

原版 `Town_Trader` 自带 Highmate 4%，兵种级概率会与阵营级 `xenotypeSet` 叠加：

1. 在 Hussar 100% 设置下生成两个新阵营的商队。
2. 商队领队/交易员不能作为严格的 Hussar 100% 断言样本；若出现 Highmate，记录为原版 Town_Trader +4% 例外，不判定本模组失败。
3. 商队守卫仍可用于战斗异种测试；Highmate 不能作战，因此不应被用于袭击战斗样本。
4. 回归检查原版外来者商队，确认本模组没有修改原版 FactionDef 或 PawnKindDef。

## F. DebugAction 设置检查

1. 进入地图并启用开发者模式。
2. 在 Debug actions → Mixed Peoples Factions 运行 `Validate settings and rebuild xenotype sets`。
3. 日志应输出设置合法性和两个阵营重建后的概率。
4. 正常 UI 只能产生 0–100 值，应显示“设置检查：通过”。若手工破坏设置文件为越界/非有限值，动作应规范化后重建并报告异常。
5. DebugAction 在开发者模式关闭时不应出现在玩家正常 UI 中。

## G. 存档与回归

1. 读取启用本模组前创建的旧世界：应无红字，但不会自动加入两个新阵营，这是预期限制。
2. Biotech 启用时保存设置，禁用 Biotech 后启动：异种段隐藏、无红字；重新启用 Biotech 后设置字典仍可读取。
3. 暂时移除含自定义 XenotypeDef 的模组：遗留设置键不得参与当前总权重；重新启用后键值可继续使用。
4. 确认原版 OutlanderCivil/OutlanderRough 的颜色、关系、异种概率和商队兵种未被污染。
