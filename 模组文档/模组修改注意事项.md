# 模组修改注意事项

1. 玩家品牌使用“阵营种族多样性 / Faction Race Diversity”和 `FRD_` 文本键；旧目录、程序集、命名空间、PackageID、`MPF_Mod`、`MPF_Settings`、旧设置键和两个 `MPF_` FactionDef defName 是存档兼容标识，不得随意删除。
2. 当前设置 schema 为 6。旧阵营级 `xenotypeWeights` 只迁移到默认 Race 的独立异种池；所有保存配置统一转换为直接 Race 比例。两个内置阵营的原始规则必须永远为所有已发现 Humanlike Race 等权，且原始均分状态不得绿色置顶。
3. 外部阵营默认遵循原始规则。不得在启动时无条件覆盖全部阵营。
4. Race 注册必须从安全 PawnKind 反查，并要求 `ThingCategory.Pawn`、Pawn thingClass、Humanlike、非尸体。必须排除 `Corpse_*`、`UnnaturalCorpse_*`、CreepJoinerForm、mutant、Boss 和无普通 PawnKind 的伪 Race。
5. `useFactionXenotypes` 只表示异种来源，不是 Race/PawnKind 角色兼容条件；不得再次要求目标 PawnKind 与原 PawnKind 的该字段相等。
6. Race 和 Xenotype 必须在 `PawnGenerator.GenerateOrRedressPawnInternal` 的最终 Prefix 中原子决定。普通 PawnGroup 预选的 `ForcedXenotype` 是软选择，可由目标 Race 独立池替换；任务/场景明确强制的异种必须保留。
7. 每个 Race 的异种池分别归一化。“HAR 允许使用”只代表兼容性，不代表归属。PawnKind/Faction XenotypeSet 只有正概率条目才能建立归属，零概率占位禁止显示为可配置异种；Human 必须排除已归属非人类 Race 的异种。
8. 战斗请求必须过滤 `canGenerateAsCombatant == false` 的异种；和平请求可以使用 Race 允许的其他异种。
9. 异种应用继续遵守运行时所有权：恢复时只有当前 `FactionDef.xenotypeSet` 仍等于本模组写入对象才可恢复。
10. 禁止克隆运行时 PawnKind、修改共享 `PawnKindDef.race`、整体替换 `pawnGroupMakers` 或向第三方列表追加不受控条目。
11. Harmony ID 固定为 `yyyyy.factionracediversity`。PawnGroup 补丁只维护本模组自己的 `[ThreadStatic] Stack`；Finalizer 必须保证异常时弹栈。
12. 与阵营文化多样性共存时，不得写 `FixedIdeo`、`ForceNoIdeo`、`Pawn.Ideo`、`Faction.ideos`、Pawn 所属阵营，也不得清理其缓存。
13. 阵营列表中隐藏/不可用默认不显示；活动配置阵营必须始终可见、绿色并置顶。玩家界面不得显示 defName、PackageID 或补丁标识。
14. 阵营图标优先检查 `factionIconPath`，为空时再使用 `settlementTexturePath` 或阵营色块；不要直接使用会返回 BadTex 的空路径缓存作为存在判断。
15. 所有新增兼容必须遵守 `模组文档/种族兼容基本规则.md`。普通 PawnGroup 的解析顺序固定为精确映射、自动匹配、通用角色后备；Human 权重为 0 且存在完整兼容配置时不得保留 Human。不得依赖 70/100 次生成重试、Validator 或生成后改 race。
16. 设置只影响新生成 Pawn；不通过 tick、换阵营或 Redress 改写既有人物。
17. Def 或翻译修改后必须刷新 `Wiki/` 并补回“游戏解释”列；C# 修改后必须 Release 构建、运行静态测试并清理 bin/obj/PDB。
18. 阻断修复发布前必须实测：Ratkin 100%、Axolotl 100%、Ratkin/Axolotl 50/50、Human 0%、袭击/援军/访客、商队商人/护卫/人形商品、平民/商人/领袖/破墙手、三 Race 独立异种池及文化多样性联合运行。
19. 第二批兼容必须区分 Race 本体与 Gene Patch：Kiiro/Wolfein Gene Patch 只条件追加 Xenotype，Ratkin Gene Expanded 只扩展现有 Ratkin 配置；不得创建同 Race 的第二个兼容 Def 覆盖原配置。Epona 的 Epona/Destrier/Unicorn，以及 Milira Gene Patch 条件加载的瓦尔基里/派卡萨斯必须分开建表；`Milian_Race`、机械单位和缺少普通安全 PawnKind 的联动 Race 不得纳入。
20. Gene Patch 启用后的专属异种池必须条件排除本体遗留 `Baseliner`，但本体单独启用时仍保留它。外层 `Combat` PawnGroup、`MustBeCapableOfViolence` 或来源战士请求的所有替换路径都必须选择 `isFighter == true` 的 PawnKind；战斗后备禁止降级到平民。
21. 同一 Race 的阵营扩展不得另建重复 `FRD_RaceCompatibilityDef`。每个扩展必须在本体配置中使用 `MayRequire` 条件登记 13 组 PawnKind 映射、四类后备和一致 `variantId`；无效条件目标必须保留本体后备，多扩展并存不得互相覆盖。
22. 第三批兼容固定包含 Dragonian_Race、Kurin_Race、Moosesian、Yuran_Race、Yuran_Race_Miko、Yuran_Race_Miko_BlackSnake。Yuran 三个 Race 分开建表；式神、Milian 机械单位与其他非普通 Humanlike PawnKind 不纳入。
23. 所有 Race 配置共用 `FRD_FirstPartySupportedFactions`；新增来源派系应先进入共享集，不得把同一派系列表复制到 15 个 Race Def。共享集内仍必须逐项核对真实 FactionDef 与 PackageID。
24. 同 Race 多阵营扩展必须为每组 13 角色映射和对应 `fallbackOverrides` 使用同一 `variantId`。单扩展保持覆盖行为；多扩展按派系稳定选择，禁止恢复“最后加载项覆盖全部派系”。
25. `Milira: Wings of Democracy` 的米莉拉人物是任务专用，`Wolfein Race GFI Expand` 仅有机械 PawnKind；除非来源后续提供普通 Humanlike 派系角色表，否则不得把这些任务人物或机械单位设为通用后备。
26. 美狐星环兼容依赖 `src.Core.markeazzyh`，Race 为 `Alien_Miho`。只登记正概率天狐异种和普通美狐 PawnKind；`SR_Faction_SRC`、`SR_Faction_SRC_Researcher`、任务教授及 `SR_*` 机械 Race/PawnKind 不得进入普通兼容。 Miho 本体派系 `Miho_Faction_Supremacist` 属于可调人形派系；本体正概率原生异种必须包含 `Xeno_CelestialMiho_Desert`，并显式排除 `Baseliner`。

27. 瓦尔基里 `Alien_Epona_Milira` 与派卡萨斯 `Alien_Unicorn_Milira` 只有来源模组提供的单一通用 PawnKind。仅这两个配置可启用 `allowUniversalRoleFallback`；异种池必须分别锁定 `Xeno_EponaMilira` 与 `Xeno_UnicornMilira`，并排除 Epona/Destrier/Unicorn、本体另一混血异种和 `Baseliner`。

28. 原版 `ValidatorPostGear` 会校验特殊袭击策略的实际 Pawn 与装备。手动映射、自动匹配和通用后备都必须保留来源 PawnKind 的 `canBeSapper`、`isGoodBreacher`、`isGoodPsychicRitualInvoker`；`allowUniversalRoleFallback` 只能放宽普通战斗/商人/领袖标记，不能放宽这些特殊策略角色。

29. 玩家自定义异种只从原版 `CharacterCardUtility.CustomXenotypesForReading` 的磁盘预设目录读取，不得合并 `Current.Game.customXenotypeDatabase` 或把预设伪装成 `XenotypeDef`。新预设在所有 Race 下默认 0；非 Human Race 的正权重表示玩家显式允许。选择时 `ForcedXenotype` 与 `ForcedCustomXenotype` 必须互斥，已有硬指定 Custom 必须保留，战斗请求必须过滤禁用 `WorkTags.Violent` 的预设。
