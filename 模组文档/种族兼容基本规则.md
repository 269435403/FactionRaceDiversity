# 种族兼容基本规则

本文件是“阵营种族多样性”后续兼容工作的固定规范。新增或调整任何 Race、PawnKind、Xenotype、Faction 兼容时，必须先更新本规则，再按规则修改兼容 Def 与测试。

## 一、兼容目标

一个种族模组要进入某个派系，必须同时完成四层兼容：

1. **Race 层**：目标 ThingDef 是真实、可生成、Humanlike 的 Pawn Race；
2. **Xenotype 层**：明确登记该 Race 的原生异种，且 HAR 允许该 Race 使用；
3. **Faction 层**：明确列出允许使用该 Race 的目标 FactionDef；
4. **PawnKind 层**：为目标派系可能请求的 PawnKind 指定同种族替代 PawnKind。

四层均有明确证据时使用手动兼容。缺少精确 PawnKind 时，按本文件的后备规则处理。

## 二、数据依据

每次兼容必须核对：

- 目标种族模组的 About.xml、LoadFolders.xml；
- Race ThingDef 与 HAR raceRestriction；
- PawnKindDef 的继承链、Race、商人/领袖/战斗标记、年龄与发育阶段；
- XenotypeDef、PawnKind xenotypeSet、原生 Faction xenotypeSet；
- 原版/DLC或目标派系的 basicMemberKind、pawnGroupMakers、traders、guards；
- 简体中文 DefInjected 与 Keyed 翻译。

不得只凭名称猜测 defName、角色或异种归属。

## 三、PawnKind 角色分组

每个兼容种族至少指定四个通用后备 PawnKind：

- 通用平民；
- 通用战斗成员；
- 通用商人；
- 通用领袖。

同一 Race 的阵营扩展不得创建第二个兼容 Def 覆盖本体配置。扩展提供的新兵种必须在本体 Race 配置中使用 `MayRequire` 条件追加精确映射，并通过 `fallbackOverrides` 条件替换四类后备；每组映射与后备使用同一 `variantId`。只启用一个扩展时，该变体继续覆盖本体角色；同时启用多个同 Race 扩展时，运行时按目标派系稳定选择一个完整变体，扩展自身派系优先匹配相同 PackageID，禁止再依赖“最后加载项覆盖全部派系”。若扩展没有真正的商人或领袖 PawnKind，可以在和平后备中降级到同 Race 安全角色，但战斗后备仍必须是 `isFighter == true`。

精确映射优先按以下角色匹配：

1. 商人；
2. 领袖；
3. 儿童/新生儿；
4. 破墙手、工兵、投弹手等特殊战斗角色；
5. 普通战斗成员；
6. 普通平民。

`MustBeCapableOfViolence` 或外层 `Combat` PawnGroup 表示这是战斗生成。原版可能把 `Villager`、`Town_Councilman` 等非战斗 PawnKind 放入这类请求，但种族替换后的目标 PawnKind 必须满足 `isFighter == true`。精确映射命中平民时应拒绝并继续自动寻找战斗角色；仍未命中时必须使用战斗后备，不能降级到平民。和平、商队和定居点组仍可保留非战斗角色。

## 四、运行时解析顺序

普通袭击、援军、访客、商队商人、护卫及商队中的人形商品按以下顺序解析：

1. 读取外层 PawnGroup 的派系配置；
2. 按玩家 Race 权重选择目标 Race；
3. 使用“Faction + Race + 原 PawnKind”的精确手动映射；
4. 未命中时使用角色严格自动匹配；
5. 仍未命中时使用该 Race 的通用角色后备 PawnKind；
6. 选择该 Race 自己的异种池；
7. 在 `GenerateOrRedressPawnInternal` 入口封口 KindDef 与 Xenotype，再交给原版生成。

当 Human 权重为 0 且目标 Race 有完整兼容配置时，普通 PawnGroup 不得以“无兼容 PawnKind”为由恢复 Human。允许降低角色精度，但不得生成 Race 与 PawnKind 不一致的 Pawn，也不得生成后再修改 pawn.def。

## 五、商队规则

商队商人和护卫直接使用商队派系。奴隶等人形商品可能先使用随机来源派系生成，再被加入商队。兼容选择必须使用外层商队派系的 Race 配置，但不得改写原生成请求的 Faction，以保留姓名、文化、背景和关系来源。

驮兽、动物商品和非 Humanlike Pawn 不进入 Race 替换与“意外种族”统计。

## 六、原始规则与设置界面

- 外部派系没有保存配置时遵循其原始规则；首次拖动任一种族或异种滑条后建立自定义配置。
- `MPF_MixedCivil` 与 `MPF_MixedRough` 的原始规则定义为：所有当前可用 Humanlike Race 永久等权；新增 Race 后自动重新均分。
- 两个内置派系处于原始均分状态时不显示绿色、不置顶；玩家修改后才视为自定义配置。
- 设置页不使用“启用种族比例”或“启用异种比例”复选框；比例始终直接显示。

## 七、严格禁止

- 不克隆运行时 PawnKindDef；
- 不修改共享 PawnKindDef.race；
- 不跨种族调用 Pawn.ChangeKind；
- 不在生成完成后直接修改 pawn.def；
- 不整体替换第三方 pawnGroupMakers；
- 不依赖 Validator 保证 Race，因为原版后段重试会忽略 Validator；
- 不用 Postfix 销毁已生成 Pawn 后重试，避免关系、阵营、任务和世界 Pawn 副作用重复。

### 特殊袭击策略与装备后验证

原版工兵、破墙和灵能仪式围攻会在装备生成后调用 `ValidatorPostGear`。Race 替换必须在精确映射、自动匹配和通用后备三条路径同时保留来源 PawnKind 的 `canBeSapper`、`isGoodBreacher`、`isGoodPsychicRitualInvoker`。没有合格目标 PawnKind 时只保留该特殊请求，不得用普通战斗 PawnKind 反复撞验证器；单一通用 PawnKind 例外也不放宽本条。

## 八、新兼容的维护流程

1. 核对术语、PackageID、Race、Xenotype、Faction 和 PawnKind；
2. 在兼容 Def 中登记 Race、原生异种、派系列表、精确映射和四类后备 PawnKind；同 Race 阵营扩展使用条件映射与 `fallbackOverrides`，不得另建重复 Race 配置；
3. 检查普通/战斗/商人/领袖/儿童角色；
4. 检查 Human 0%、单 Race 100%、多 Race 50/50；
5. 检查袭击、援军、访客、商队商人、护卫和人形商品；
6. 运行兼容表覆盖检查、Release 构建、静态测试；
7. 启动 RimWorld，输出开发者报告，确认没有普通 PawnGroup Human 回退；
8. 更新本文件、模组总文档、修改日志、测试文档和 Wiki。

## 十、已验收基线

2026-07-27，玩家确认首批 NewRatkinPlus 与 MoeLotl Race 兼容全部通过。2026-07-27 新增的 Epona、Kiiro、Milira、Nivarian、Wolfein、Dragonian、Kurin、Moosesian、Yuran，以及 Ratkin/Milira 阵营扩展和三个 Gene 扩展仍需完成游戏内矩阵验收；后续兼容不得破坏以下已验收基线：

## 十一、已发现兼容问题与固定解决规则

### 1. Gene Patch 启用后仍出现“智人种”滑条

**现象：** Kiiro Race Gene Patch 或 Wolfein Race Gene Patch 已启用，绮罗族/沃芬族的异种池仍显示 `Baseliner`（智人种）。

**原因：** 两个种族本体在没有 Gene Patch 时以 `Baseliner` 作为合法基线。Gene Patch 后虽然 PawnKind 和 HAR 白名单加入了专属异种，但本体遗留的 PawnKind、Faction 或 HAR 白名单归属仍可能把 `Baseliner` 重新认领进种族池。

**固定规则：**

- 本体单独启用时，`Baseliner` 仍是合法基线，不得无条件删除；
- 对应 Gene Patch 启用时，在兼容 Def 中条件登记 `Baseliner` 排除项；
- 异种归属必须先汇总 PawnKind、Faction、同源 Xenotype、兼容 Def 与 HAR 白名单，再统一应用排除项；
- 被条件排除的 `Baseliner` 不得因“异种池为空”的安全回退再次加入；
- Kiiro Gene Patch 的最终池只保留 `KiiroXenotype`；Wolfein Gene Patch 的最终池只保留普通沃芬与纯血沃芬两个异种。

### 2. 袭击和军事支援生成无战斗能力的平民

**现象：** 召唤袭击或军事支援时，部分 Race 使用了平民 PawnKind。

**原因：** 原版战斗 PawnGroup 可能以非战斗 PawnKind 作为来源请求；旧兼容逻辑优先保持来源 `isFighter` 角色或直接接受平民精确映射，没有把外层 `Combat` PawnGroup 作为强制战斗条件。

**固定规则：**

- 外层组为 `PawnGroupKindDefOf.Combat`、请求要求暴力能力，或来源 PawnKind 本身是战士时，统一视为战斗生成；
- 同 Race 保留、精确映射、自动匹配和通用后备四条路径都必须检查目标 `PawnKindDef.isFighter == true`；
- 非战斗来源命中平民映射时不得立即使用，应继续寻找同 Race 战斗 PawnKind；
- 战斗后备不得再按平民、商人、领袖顺序兜底；找不到战斗 PawnKind 时宁可保留原生成规则，也不能生成无战斗能力的替换平民；
- 必测入口包括袭击、敌对增援、盟友军事支援和要求特定破墙/投弹角色的袭击策略。

### 3. 同 Race 阵营扩展启用后仍只出现本体 PawnKind

**现象：** 已启用金鸢尾兰鼠族阵营或米莉拉帝国阵营，但把其他派系调整为 Ratkin/Milira 后，生成结果仍只使用种族本体的通用 PawnKind。

**原因：** 本体兼容的精确映射先于通用后备命中；仅把扩展 PawnKind 加进 Race 注册表或另建同 Race 配置，分别会导致扩展兵种无法稳定出现或覆盖顺序不安全。

**固定规则：**

- 同一 Race 永远只保留一个 `FRD_RaceCompatibilityDef`；
- 阵营扩展在该配置的 `pawnKindMappings` 末尾按 `MayRequire` 条件追加同一批来源角色，使后加载映射覆盖本体目标；
- 同时使用条件 `fallbackOverrides` 替换平民、战斗、商人、领袖后备，保证未列出的普通来源角色也优先落到扩展 PawnKind；
- 条件目标失效、Race 不匹配或 PawnKind 不安全时保留本体后备，不得把整个配置置空；
- 扩展没有合格商人/领袖时允许同 Race 角色降级，但 Combat 请求只能使用战斗 PawnKind；
- 必测扩展启用/禁用切换、Human 0%、普通袭击、援军、访客、商队和保存重载。
